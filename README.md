## 과제 2종

### 1. 도형 순서 기억하기 (현행) — `shape-nback`

**실제 역검에서 쓰이는 형태.** 공개 자료 2건을 대조해 절차를 맞췄다.

- 중앙 카드 더미에 도형이 한 장씩 갱신. **도형 5종**(별·반원·마름모·원·삼각형), 동일 색상
  - 참고 자료의 원 검사는 3종이었다. 5종은 한 장이 담는 정보량을 늘려 기억 부하를 올린 변경이다
- **1라운드 2-back** — 3번째 도형부터 판단
  - 2번째 전과 일치 → `←` · 불일치 → `Space`
- **2라운드 2&3-back** — 4번째 도형부터 판단
  - 2번째 전 일치 → `←` · 3번째 전 일치 → `→` · 둘 다 아님 → `Space`
- **노출 1,500ms** 뒤 다음 도형으로 갱신. 갱신 간격 300ms
- **응답 허용 창 1,800ms** — 도형이 사라진 뒤 공백 구간까지 판단을 받는다. 노출과 응답 창을 묶어 두면 노출을 줄이는 순간 응답 시간도 깎여 작업기억이 아닌 손 속도를 재게 된다
- 남은 시간은 **채워지는 막대**로 표시된다. 눈금이 있어 진행 위치가 읽히고, 응답이 확정되면 막대가 초록으로 멈춘다
- **입력을 받는 동안만 키가 활성**된다. 도입 자극(앞 2~3장)과 응답 후에는 실제로 비활성 — 눌릴 것처럼 보이는데 무시되면 혼란스럽다
- Space 키 문구는 **라운드마다 다르다**. 1라운드는 비교 대상이 하나뿐이라 "2번째 전과 다름", 2라운드는 "둘 다 아님". 1라운드에 "둘 다 아님"은 틀린 문구다
- 속도 과제이므로 **취소 기능이 없다**
- 1라운드 36자극 · 2라운드 44자극. 본 검사 약 2분 30초

측정 구인은 **작업기억 갱신·감시(updating/monitoring)**다.

### 2. 도형 순서 기억 (고전) — `spatial-span`

Corsi Block-Tapping Test. 9개 도형 중 일부가 순차 점등되고 같은 순서로 재현한다.
측정 구인은 **시공간 작업기억 용량(span)**.

> **정정.** 처음에는 역검의 "도형 순서 기억하기"를 Corsi span으로 판단했으나 **틀렸다.**
> 실제로는 N-back이다. 두 과제는 관련되지만 다른 것을 재고(용량 vs 갱신), 채점 방식도
> 다르며(span vs d′), 참조할 문헌과 규준도 다르다. Corsi 구현은 그 자체로 유효한
> 계측기지만 역검의 해당 게임에 대응하지는 않는다.

## 영상면접 프로토타입 — `interview.html`

설계도(`바탕화면/영상면접-설계도.html`) §10의 2~4번을 구현했다. **표정·감정 추론은 하지 않는다.**

```
사전고지·동의 → 장비 점검(말해서 확인) → 연습 → 본 면접 6문항 → 저장 확인 → 전사 확인·정정 → 제출 → 검토자 화면 → 산출근거 설명
```

- **녹화**: 브라우저 MediaRecorder, 640×480·15fps(수집 최소화), 5초 구간으로 잘라 저장. 중간에 끊겨도 부분 손실만
- **저장·파기**: IndexedDB(프로토타입). `retentionUntil` 기반 자동 파기가 로드마다 돌고, 조회·파기 이력을 남긴다. 운영은 암호화 객체 저장소로 교체
- **전사 정정**: 문항당 3회, 편집거리 상한 15%(최소 20자). 원문·정정본·거부된 시도까지 전부 기록 — 오인식은 고치되 답변 고쳐쓰기는 막는다 (R-01·D-2)
- **마스킹**: 학교·회사·이름·지역·연락처를 지운 뒤에만 채점기에 보낸다 (R-03). 검토자 화면에서 마스킹 결과를 미리 본다
- **행동 지표**(첫 발화 지연·발화 길이·말속도): 기록만, 점수 미반영 (R-06)

| 종류 | 기본 | 외부 전송 | 교체 대상 |

| TTS | 브라우저 내장 음성합성 | 없음 | 운영 TTS |

### 테스트 모드 — 지원 안 되는 단계를 건너뛴다

`interview.html?test=1&fast=1`

- 상단에 빨간 띠, **단계 표시줄**(1 고지 → … → 8 기록)이 뜨고 도달 가능한 단계는 클릭으로 이동
- 게이트마다 건너뛰기: 동의 없이 → 장비 없이(녹화 생략, 타이머·전사만) → 문항 건너뛰기 → **본 면접 건너뛰고 픽스처로 채우기**
- 고지 화면의 "녹화 없이 픽스처로 채우고 저장 확인으로"를 누르면 카메라 없이 바로 전사·채점·검토 화면까지 간다
- `fast=1`: 준비 3초·답변 6초
- `test=1`만 주면 stt=fixture, scorer=mock, tts=null이 기본

**우회한 사실은 전부 `session.bypasses`에 남고** 저장 확인·제출·기록 화면에 빨간 띠로 표시된다. 지원 환경 검증은 그대로 두되, 테스트 목적으로 다음 단계로 갈 수 있게 한 것이지 검증을 없앤 것이 아니다.

테스트용 공급자 — API 없이 화면을 끝까지 돌린다:

| 쿼리 | 효과 |
|---|---|
| `?stt=fixture&scorer=mock` | 고정 전사(식별자 포함·저신뢰 1문항) + 모의 채점. **전사 정정·마스킹·채점 결과·근거 인용·검토자 채점·일치도**를 전부 볼 수 있다 |
| `?stt=manual` | 녹화 뒤 직접 타이핑. 실제 발화로 정정 화면을 시험할 때 |
| `?stt=webspeech-dev` | 브라우저 음성인식. **외부 전송되므로 개발 확인용**, 고지 화면에 빨간 경고 |

모의 채점기는 휴리스틱이며 타당도가 없다 — 화면과 데이터 모양(서버 채점기와 동일)을 검증하는 용도다. 모든 공급자는 `external`(외부 전송 여부)을 boolean으로 밝혀야 등록된다.

### 검토자 채점 화면

기록 보기 화면 하단에서 사람이 특성별 1~5점과 **근거 문장(드래그 선택 → 오프셋 기록)**을 남긴다. `humanScore`로 저장되며 캘리브레이션과 타당도 연구의 원자료다. 자동 점수가 있으면 정확 일치·±1·평균 차이를 보여준다 — 표본 1건에서는 수치에 의미가 없다.

### 편향 회귀 테스트 — `tests/bias.test.js`

이름·학교·회사·지역만 다른 답변 쌍(`fixtures/bias-pairs.json`)이 **마스킹 후 동일**해지고 **채점기가 같은 점수·근거**를 내는지 확인한다. 이 테스트가 마스킹 결함 두 개를 잡았다: 접미사 없는 회사명(네이버·카카오)을 놓쳤고, `(주)X에서`에서 조사까지 삼켜 두 답변이 달라졌다. 실제 채점기가 붙으면 같은 쌍으로 `--dry-run` 요청 본문을 비교한다.

### 서버 채점 — `server/`

`server/score-claude.mjs`가 세션 JSON을 받아 마스킹 → 근거 인용(Citations) → 점수(구조화 출력) 순으로 처리한다. `--dry-run`이면 키 없이 요청 본문만 출력한다. 영상·음성은 보내지 않는다. 자세한 건 `server/README.md`.

## 채점

### N-back — 조건별 d′ (신호탐지이론)

정답률만 쓰면 **아무 때나 `←`를 누르는 응시자를 걸러낼 수 없다.** 적중률은 높아지지만
실제 변별력은 없기 때문이다. 그래서 적중과 오경보를 함께 쓴다.

```
d′ = z(적중률) − z(오경보율)
반응편향 c = −(z(적중률) + z(오경보율)) / 2
```

- log-linear 보정(Hautus)을 적용해 적중률 100%·오경보 0%에서 d′가 무한대로 발산하는 것을 막는다. 짧은 검사에서는 필수
- **2-back과 3-back을 합치지 않는다.** 같은 라운드 안에서 3-back의 d′가 2-back보다 낮게 나오는지가, 이 과제가 실제로 작업기억 부하를 재고 있는지 확인하는 근거다
- `c`가 크게 음수인데 d′가 낮으면 실력 부족이 아니라 **전략 문제**다. 리포트에서 구분한다

### Corsi — Span × 정답 시행 수

- **Corsi Span** = 정답으로 재현한 가장 긴 순서 길이
- **Total Score** = Span × 정답 시행 수 (Kessels et al., 2000)

두 과제 모두 반응시간은 점수에서 제외하고 보조 지표로만 보고한다.

### 과제 추가하는 방법

파일 하나를 만들고 `Tasks.register()`를 호출하면 끝이다. 셸·리포트·설명 화면은 손대지 않는다.

```js
Tasks.register({
  id, label, subtitle,
  consent: { measures, scoring, collects },   // 사전고지 문구
  walkthrough: [ { title, body, html } ],     // 스텝별 설명. html은 과제가 만든 예시 그림
  readyNote,                                  // 본 검사 시작 경고
  create(o),        // o = { stage, rng, phase, onTrial, onStatus }
  score(trials), normKey(s),
  tiles(s), sections(ctx), logTable(ctx), explain(ctx)
});
```

인스턴스는 `runPractice()` / `runLive()` / `abort()`를 갖고, 선택적으로 `destroy()`,
그리고 취소 기능이 있는 과제만 `undo()` / `submit()`을 갖는다. 셸은 있으면 쓰고 없으면 숨긴다 —
N-back은 속도 과제라 취소가 없고, 그래서 취소 UI가 나타나지 않는다.

## 계측기로 만든 근거

**시드 RNG** — `session.seed` 하나로 응시자가 본 모든 자극을 재현한다. 분쟁 시 "이 사람이 정확히 무엇을 봤는가"를 증명해야 하므로 `Math.random()`은 쓸 수 없다.

**규준 게이트** — 규준 표본 `n < 300`이면 백분위·등급 산출을 **코드가 거부한다.** 규준 없는 "상위 20%"는 허위 표시다.

**자극열 무효 문항 배제** — 2&3-back에서 현재 도형이 2번째 전과 3번째 전에 동시에 일치하면 정답이 둘이 된다. 생성 단계에서 이 자리를 배제하고, 표적을 놓을 수 없는 자리는 비표적으로 낮춘 뒤 **실제로 놓인 라벨을 기록한다** — 채점은 스케줄이 아니라 이 기록을 따르므로 항상 정확하다.

**불규칙 배치 (Corsi)** — 격자는 위치를 "좌상→우하" 식으로 언어화시켜, 시공간 작업기억 대신 언어 작업기억을 측정하게 된다.

**정오 미고지 (연습 포함)** — 맞았는지 알려주면 응시자가 그 정보로 판단 기준을 바꿔(학습 효과) 시행 간 독립성이 깨지고, d′가 능력이 아닌 적응 속도를 반영하게 된다. 응시 중 화면에 표시하는 것은 **응답 / 무응답** 뿐이다. 안 누른 사실은 알려준다 — 다음 자극에 대비할 정보이고 정오가 아니기 때문이다.

**정오는 리포트에서 전부 공개** — 기업용이므로 응시자가 이의제기하거나 인적 재검토를 요청할 때 쓸 근거가 남아야 한다. 마지막 리포트의 원시 로그에 자극별 **정답 조건 · 누른 키 · 판정(적중/누락/오경보/정확기각/무응답)** 을 모두 표기한다. 가리는 것은 응시 중뿐이다.

**RT 점수 제외** — 브라우저·기기별 계통 오차가 선행 연구에서 확인됐다. 실측 리프레시 레이트를 로그에 쌓아 보정 근거를 만들되, 그때까지는 정확도 기반 점수만 낸다. 단 N-back의 무응답은 오류로 채점한다 — 허용 시간 안에 판단하지 못한 것 자체가 과제 수행의 일부다.

**제한된 오입력 복구 (Corsi만)** — 취소를 금지하면 마우스 실수가 점수에 섞이고, 무제한 허용하면 "눌러보고 취소"로 자극 시연을 연장해 다른 능력을 재게 된다. 본 검사 시행당 1회·2초 이내, 입력 완료 후 2초 확정 유예. 전 취소를 `sinceTapMs`와 함께 기록해 **손 실수와 망설임을 분류**한다.

**무응답 상한** — 없으면 응시자 이탈 시 시행이 영구히 종료되지 않는다.

**스텝별 과제 설명** — 규칙을 글로만 늘어놓으면 "2번째 전"이 무슨 뜻인지 응시자가 알기 어렵다. 실제 자극과 같은 도형으로 카드 띠를 그려 **어느 카드와 어느 카드를 비교하는지 괄호로 표시하고, 그때 눌러야 할 키를 함께 보여준다.** 예시의 도형 배열이 제시한 정답과 실제로 맞는지는 테스트가 검산한다 — 설명이 틀리면 응시자를 오도하기 때문이다.

**가이드 레이아웃 고정** — 스텝마다 글 길이와 그림 높이가 달라 '다음' 버튼이 위아래로 튀면 누르기 불편하다. 본문 최소 높이·예시 영역 고정 높이·마지막 안내문 자리를 예약해 버튼을 한자리에 묶었다. 그림이 없는 스텝도 영역을 숨기지 않는다.

**설명 화면 (§37조의2)** — 점수 공식에 실제 값을 대입한 전개, 수집 항목별 목적, 거부·인적재검토·삭제 요청. 법무 문서가 아니라 제품 기능이다.

## 미결 결정 — 규준 수집 착수 전 확정 필요

규준을 모으기 시작하면 아래가 고정된다. 이후 변경하면 그때까지 모은 규준이 폐기된다.

### Corsi — 계단 진급 규칙

시뮬레이션(각 400회) 결과 진짜 span → 측정 span 평균:

```
3 → 3.42    4 → 4.45    5 → 5.40    6 → 6.34    7 → 7.46
```

단조증가(변별력)는 확인됐으나 **일관되게 +0.35~0.46 과대추정**된다. 현행 `2시행 중 1회 정답 → 진급`이
관대해 우연히 맞힌 1회로도 올라가기 때문이다.

| 규칙 | 편향 | 시행 수 |
|---|---|---|
| 2중 1회 (현행) | +0.4 과대 | 기준 |
| 2중 2회 | 감소 (하향 편향 가능) | 유사 |
| **3중 2회** (Kessels 변형) | 최소 | +50% |

### Corsi — 블록 좌표

현 9점 좌표는 **논문 원문을 대조하지 않고 직접 생성한 값**이다. 출판된 Corsi 규준을 참조하려면
원본 배치와 같아야 한다.

### N-back — 시행 수와 표적 비율

자료에 공개되지 않은 값이라 방어 가능한 선에서 정했다. 1라운드 36자극(표적 32%),
2라운드 44자극(2-back 20% + 3-back 20%). 노출을 1.5초로 줄인 만큼 자극 수를 늘려
**조건별 표적을 8개씩** 확보했다 — d′의 표준오차는 시행 수에 직접 좌우되므로 이게 곧 측정 정밀도다.
그래도 개인 수준의 확정 판단에는 여전히 부족하다. 선발에 쓰려면 조건별 20회 이상이 필요하다.

### N-back — 도형 수

원 검사는 3종, 현재 구현은 5종이다. 도형이 늘면 한 장이 담는 정보량이 늘어 부하가 올라가고,
우연히 앞 카드와 겹칠 확률이 낮아져 비표적 자극을 만들 여지도 넓어진다. **원 검사와 점수를
비교할 수 없게 되는 변경**이므로 규준 수집 전에 3종/5종을 확정해야 한다.

### N-back — 노출 시간

1,500ms 노출 + 300ms 공백(응답 허용 1,800ms). 원 검사의 실제 값은 공개되지 않았고, 참고한 자료는
"약 3초"로 관찰했으나 실제 사용감에 맞춰 1.5초로 조정했다. **부하가 달라지면 점수가 비교 불가능해지므로**
규준 수집 전에 확정해야 한다.
