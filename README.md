# 도형 순서 기억 — 역량검사 프로토타입

Corsi Block-Tapping Test 기반 시공간 작업기억 측정 도구. 게임 1종을 만든 것이 아니라, **여러 인지과제가 올라갈 측정 파이프라인을 1종으로 관통시킨 것**이다.

## 실행

`index.html` 더블클릭. 빌드 도구·서버·의존성 없음.

`file://`에서 ES 모듈이 차단되므로 클래식 `<script>` 구성을 유지한다.

## 테스트

```bash
npm test
```

Node만 필요하다. 최소 DOM 스텁으로 과제 상태기계까지 헤드리스 검증한다.

## 흐름

```
사전고지·동의 → 과제 설명 → 연습 2시행(피드백 O) → 본 검사(피드백 X) → 리포트 → 산출근거 설명
```

## 설계 근거

그냥 게임이 아니라 평가 도구로 만들기 위해 넣은 것들.

**1. 시드 RNG** — `session.seed` 하나로 응시자가 본 모든 자극을 재현할 수 있다. 채용 분쟁 시 "이 사람이 정확히 무엇을 봤는가"를 증명해야 하므로 `Math.random()`은 쓸 수 없다.

**2. 규준 게이트** (`Core.Norms`) — 규준 표본 n < 300이면 백분위·등급 산출을 **코드가 거부한다**. 규준 없는 "상위 20%"는 허위 표시다. 규준 확보 시 `Core.Norms.tables`에 주입하면 자동 개방된다.

**3. 불규칙 배치** — 격자 배치는 위치를 언어적으로 부호화(좌상→우하 등)하게 만들어, 시공간 작업기억 대신 언어 작업기억을 측정하게 된다. 고전 Corsi 보드 배열을 따랐다.

**4. 본 시행 비피드백** — 표준 절차. 피드백은 학습 효과를 만들어 시행 간 독립성을 깨뜨린다. 연습에서만 제공한다.

**5. RT를 점수에 넣지 않음** — 브라우저·기기별 반응시간 계통 오차가 선행 연구에서 확인되었다. `browserTimingCaps`(실측 리프레시 레이트)를 로그에 남겨 보정 근거를 쌓되, 그때까지는 정확도 기반 점수만 산출한다.

**6. 제한된 오입력 복구** — 취소를 전면 금지하면 마우스 조작 실수가 점수에 섞인다. 반대로 무제한 허용하면 "눌러보고 취소"로 사실상 자극 시연을 연장할 수 있어 다른 능력을 측정하게 된다. 따라서:

- 본 검사: **시행당 1회**, 마지막 입력 후 **2초 이내**
- 연습: 무제한 (기능 학습 목적)
- 입력 완료 후 **2초 확정 유예** — 없으면 가장 치명적인 실수(마지막 클릭 오타)를 복구할 수 없다
- 모든 취소는 `sinceTapMs`와 함께 기록된다. 이 값이 짧으면 **손 실수**, 길면 **망설임**(기억 불확실)으로 분류해 리포트에 표시한다

**7. 무응답 상한** — `8초 + 순서당 2.5초`. 없으면 응시자 이탈 시 시행이 영구히 종료되지 않는다.

**8. 무결성 이벤트** — 본 시행 구간의 탭 이탈·포커스 상실·창 크기 변경을 기록한다.

**9. 자동화 결정 설명 화면** — 측정 대상, 절차, 점수 공식에 실제 값을 대입한 전개, 수집 항목별 목적, 그리고 거부·인적재검토·삭제 요청 버튼. 법무 문서가 아니라 **제품 기능**으로 구현했다.

## 채점

- **Corsi Span** = 정답으로 재현한 가장 긴 순서 길이
- **Total Score** = Span × 정답 시행 수 (Kessels et al., 2000)
- 반응시간은 보조 지표로만 보고

## 검증 상태

`npm test` — **93개 검사 통과** (순수 로직 43 + 과제 상태기계 50).

커버 범위: 시드 재현성·비복원 추출, 채점 경계값(전부 오답·빈 배열), 규준 게이트(n 미달 시 차단), 로거 스키마, 무결성 구간 필터, 계단 절차 시뮬레이션 2,000회, 취소 횟수·창 만료·확정 유예·마지막 입력 복구, 무응답 상한, 타이머 누수.

**대화형 UI는 사람 눈 확인이 필요하다** — 개발 환경에 헤드리스 브라우저가 없어 렌더링·클릭 흐름은 자동 검증하지 못했다.

## 알려진 이슈 — 계단 절차 상향 편향

시뮬레이션 결과 (진짜 span → 측정 span 평균, 각 400회):

```
3 → 3.42    4 → 4.45    5 → 5.40    6 → 6.34    7 → 7.46
```

단조증가(변별력)는 확인됐지만 **일관되게 +0.35~0.46 과대추정**된다. 원인은 진급 규칙(`2시행 중 1회 정답 → 진급`)이 관대해서, 우연히 맞힌 1회로도 다음 단계에 올라가기 때문이다.

| 규칙 | 결과 | 비용 |
|---|---|---|
| 현행: 2중 1회 정답 진급 | +0.4 과대추정 | 시행 수 적음 |
| 2중 2회 정답 진급 | 편향 감소, 하향 편향 가능 | 시행 수 유사 |
| **3중 2회 정답 진급** (Kessels 변형) | 편향 최소 | 시행 수 +50% |

**규준을 수집하는 순간 규칙이 고정된다.** 규칙이 바뀌면 기존 규준은 폐기되므로 규준 수집 착수 전에 결정해야 한다. 오입력 복구 정책도 같다.

## 과제 추가하는 방법

`js/task-spatial-span.js`를 복제해 아래 인터페이스만 맞추면 `core`·`report`·`app`은 그대로 재사용된다.

```js
new Task({ board, rng, phase, onTrial, onStatus })
  .runPractice() -> Promise
  .runLive()     -> Promise
```

`onTrial`에 넘기는 객체는 `core.js`의 Trial 스키마를 따를 것:

```js
{
  taskId, phase, trialIndex, difficulty,
  stimulus, response, correct,
  rtFirstMs, rtFirstRawMs, rtTotalMs, interTapMs,
  undos, undoCount, timedOut, tsClient, abandoned
}
```
