# 평가자 프로토콜 — 채점 표본 DB 만들기

- 목적: 자동 채점기를 교정하고 타당도를 검증할 **사람 점수 표본**을 만든다
- 답변 출처: AI Hub 채용면접 인터뷰 데이터(한국어 실제 답변) + 자체 프로토타입 세션
- 원칙 한 줄: **답변은 이미 있다. 우리가 만드는 건 점수다.**

---

## 1. 표본 설계

| 항목 | 값 | 이유 |
|---|---|---|
| 1차 표본 | 문항 유형별 60건 × 6유형 = **360건** | 특성별 κ 계산에 최소 필요. 교정 회귀는 30건이면 시작되지만 유형별로 갈라야 한다 |
| 직군 분포 | AI Hub 직군 7종에서 고르게 | 특정 직군 어휘에 채점기가 편향되는지 볼 수 있다 |
| 평가자 수 | **2명 독립** + 조정자 1명 | κ는 2명이면 계산된다. 3명이면 더 좋지만 비용이 1.5배 |
| 제외 | 전사 신뢰도 < 0.6, 20자 미만, 질문과 무관 | 자동채점도 같은 기준으로 제외하므로 표본을 일치시킨다 |

**답변 선택은 무작위**여야 한다. 좋은 답변만 고르면 척도의 아래쪽이 비고, 교정이 위쪽으로 쏠린다.

## 2. 평가자 훈련

1. 루브릭(`rubric-0.1.0`)의 특성 5개와 앵커(1·3·5)를 읽는다
2. **앵커 답변 15건**(특성별 1·3·5점 예시 3건씩)을 조정자가 미리 채점해 둔 것을 보고 함께 논의한다
3. 훈련 세트 **30건**을 독립 채점 → 조정자 점수와 가중 κ 계산
4. κ ≥ 0.70이면 통과. 미달이면 불일치 항목을 놓고 재논의 후 다른 30건으로 재시도
5. 통과한 평가자만 `raters.trained_at`에 시각을 기록한다

훈련 세트는 본 표본에 넣지 않는다.

## 3. 채점 규칙

- **말한 내용만** 본다. 말투·자신감·인상·표정에 대한 언급은 채점 근거가 될 수 없다
- 특성마다 **근거 문장을 반드시 하나 이상** 선택한다. 근거 없이 점수를 줄 수 없다 — 없으면 1점이다
- 문항에 대응하지 않는 특성은 채점하지 않는다 (예: 자기소개 문항에 `judgment` 없음)
- 마스킹된 텍스트로 채점한다. `[학교]`·`[회사]`가 무엇이었을지 추측하지 않는다
- 답변 하나에 **3분 이상 쓰지 않는다.** 오래 고민하는 것은 앵커가 모호하다는 신호이고, 그건 루브릭 문제다 — 메모에 남긴다

## 4. 불일치 처리

| 차이 | 처리 |
|---|---|
| 0~1점 | 그대로 둔다. 두 점수 모두 DB에 남는다 |
| 2점 이상 | 조정자가 제3 채점. `rating_queue.adjudicated = 1`. 세 점수 모두 남긴다 |
| 특정 특성에서 반복 | 그 특성의 앵커를 재정의하고 **루브릭 버전을 올린다** |

평균으로 뭉개지 않는다. 일치도는 평가자별 원점수에서만 계산된다.

## 5. 일치도 기준

`node db/report.mjs`가 특성별로 낸다.

| 가중 κ | 판정 | 조치 |
|---|---|---|
| ≥ 0.80 | 거의 완전 일치 | 교정 진행 |
| 0.70~0.79 | 실질적 일치 | 교정 진행 |
| 0.60~0.69 | 중간 | 평가자 재훈련 |
| 0.40~0.59 | 보통 | 앵커 재정의 |
| < 0.40 | 낮음 | 루브릭 자체를 의심 |

참고 상한: Kaggle ASAP 에세이 채점 κ = 0.86 (평가자 2명).

## 6. 자동 채점기 교정

사람 표본이 특성별 30건을 넘으면 `linearCalibration`이 계수를 낸다. 그 전까지 `auto_score_runs.calibrated`는 NULL이고 화면은 "교정 전"을 표시한다.

교정된 뒤에도 자동 점수는 **참고자료**다 (설계도 D-1). 준거관련 타당도(직무 성과와의 상관)는 별도 연구다.

## 7. 편향 점검

- 같은 답변 세트를 이름·학교·회사만 바꿔 채점기에 넣어 점수가 흔들리는지 (`tests/bias.test.js`, `--dry-run`)
- 평가자도 같다: 마스킹 전 텍스트를 보여주면 안 된다
- 직군별·성별(파악 가능한 경우)·연령대별 평균 점수 차이를 표본 단계부터 본다. 차이가 있으면 원인이 답변인지 채점인지 가려야 한다

## 8. 기록

- 평가자 id, 채점 시각, 점수, 근거 문장(오프셋), 메모 — 전부 `human_scores`·`human_evidence`
- 루브릭 버전이 바뀌면 이전 점수는 **새 버전과 비교하지 않는다**
- 표본 DB는 직접 식별자를 포함하지 않는다. AI Hub 데이터는 재배포 불가이므로 원문 텍스트를 외부에 내보내지 않는다
